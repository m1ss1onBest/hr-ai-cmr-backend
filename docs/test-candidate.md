Звіт про автоматизоване E2E тестування модуля Candidates
Огляд
Для забезпечення стабільності модуля Candidates (API v1) та перевірки відповідності бізнес-вимогам проєкту ImpactPulse, було впроваджено набір End-to-End (E2E) тестів. Тестування охоплює повний життєвий цикл кандидата: від створення з валідацією даних до механізму м'якого видалення (Soft Delete).

Опис виконаних тест-кейсів (Jira Tasks)
1. Створення та валідація (KAN-113, KAN-114, KAN-117)
Реалізовано перевірку вхідних даних (DTO) за допомогою ValidationPipe для гарантії цілісності даних:

KAN-113 (Positive): Успішне створення кандидата при передачі всіх обов'язкових полів (name, cvUrl, expectedSalary, position). Перевірено статус 201 Created.

KAN-114 (Negative): Перевірка обов'язковості полів. Система повертає 400 Bad Request, якщо відсутні критичні дані (наприклад, position або cvUrl).

KAN-117 (Invalid Data): Тестування формату даних. Система відхиляє запит, якщо поле cvUrl не відповідає формату URL-адреси.

2. Пошук та фільтрація (KAN-116, KAN-118)
Реалізовано тести для перевірки механізмів вибірки даних через Query-параметри:

KAN-116 (Search): Перевірка роботи пошуку за текстовими полями.

KAN-118 (Filtering): Тестування фільтрації списку кандидатів за ідентифікатором вакансії (positionId).

3. Видалення та Soft Delete (KAN-115)
Перевірено механізм видалення даних без їх фізичного знищення в базі:

Логіка: Замість запиту DELETE виконується UPDATE для поля deletedAt.

Статус: Тест підтверджує повернення статусу 204 No Content.

Результат: Запис залишається в базі даних із позначкою часу видалення.

Інструкція із запуску
Для виконання тестів та отримання детального звіту необхідно використати команду:

Bash
npm run test:e2e
